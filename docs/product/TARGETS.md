## Weekly scorecard and governance

The existing `.github/workflows/ai-dashboard.yml` is the only writer of `.ai/DASHBOARD.md`. It will run weekly, on `.ai/**` pushes, and manually. It reports the public approved-work count when the connected site's read-only API is available, the general category count from the source registry, the seven-day GitHub Actions run rate, documented stale-lock takeovers, task/owner-question counts, and the metrics still marked **not measured**. It must not store image URLs, personal contact details, or secrets; it must not edit this file or change any target.

Every proposed target addition, value, threshold, or removal must first be recorded in `.ai/DECISIONS.md` with its rationale and status, then receive an explicit owner Yes in `.ai/OWNER_QUESTIONS.md` before becoming active. Baseline observations may be updated without approval only when measured and sourced; they may not be silently promoted into targets. A No leaves the proposal inactive. Monetization and 18+ always retain their separate approval/policy gates.
